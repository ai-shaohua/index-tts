# 句末切分合成

日期：2026-10-18  
状态：待实现  
涉及文件：`new-server.py`、`new-webui.py`  
不改文件：`webui.py`、`server.py`

## 问题

IndexTTS 把一段发言整段送进模型。句号只影响模型自己带出来的气口，没有固定时长。逗号、顿号、分号在文本归一化里会被收成同一种逗号，长文本的分段又按 token 预算切，不按句末切。结果是音色像，句末停顿偏短，而且不可控。

狼人杀发言通常两三句。用户要的是：原文先走和推理相同的文本处理，再按句末切开，逐句生成，句与句之间用 500ms 静音按原顺序拼成一条可播放的音频。

## 目标

1. `new-server.py` 收到原文后，先做与 IndexTTS 2.5 相同的文本归一化，再只按句末标点切成句子。
2. 每个句子单独合成，按原顺序拼接。句与句之间插入 500ms 静音，最后一句后面不加这段静音。
3. `new-webui.py` 提供一个新界面：选音色、输入原文、看到切出来的句子、播放最终音频。
4. 切分、逐句生成、500ms 拼接全部在 `new-server.py` 内完成。`new-webui.py` 不加载模型，也不自己切句或拼音频。
5. `webui.py` 和 `server.py` 保持现状，行为不变。

## 非目标

- 不给逗号、顿号、分号、冒号单独加 250ms 停顿。句中停顿仍由模型生成。
- 不改文本归一化规则。数字仍读成汉字，`。！？` 仍变成 `.!?`，`，、；：` 仍变成 `,`。
- 不在界面上逐句改稿、调每句的停顿或情感。
- 不把句子生成过程流式推到播放器。界面等整段拼接完成后再播放。
- 不在 `new-webui.py` 里加载第二份模型权重。同一时刻只跑一个带模型的进程。

## 用户流程

1. 启动 `new-server.py`（默认端口 `3003`），再启动 `new-webui.py`（默认端口 `7861`）。两者可与现有的 `server.py`（`3002`）和 `webui.py`（`7860`）同时存在，但不要同时加载两份模型。
2. 在新界面选择 `wolf-audio` 里的音色，语言默认中文，粘贴发言原文。
3. 点击生成。界面先显示切句结果，再等待合成。
4. 合成结束后，播放器播放拼接好的整段音频。

## 切句规则

切句发生在文本归一化之后、逐句合成之前。归一化与 `indextts/infer_v2_5.py` 的中文路径一致：先做 `char_rep_map` 替换，再走 WeTextProcessing。界面展示的句子必须和实际送去合成的句子是同一份结果。

句末标点，切在这里，标点留在该句末尾：

- `.` `。`
- `!` `！`
- `?` `？`

不切：

- `,` `，` `、` `；` `;` `：` `:`
- `…`（由 `……`、`...` 转来）
- 换行（归一化后变成空格）

其他约定：

- 没有句末标点的剩余文本仍作为最后一句。
- 切完后去掉空句，不为空句发合成请求。
- 只有一句时不插入 500ms。
- 句末标点保留在送进模型的文本里，让该句仍有句末语调。500ms 是拼接到音频上的静音，不是再写进文本的标点。

用下面这段原文验收。归一化后应得到 3 句，而不是按逗号拆开。`；` 已经变成逗号，所以「我信逻辑」仍留在第 3 句。

原文：

```text
6号开枪，铁狼王，我是真预言家。昨夜验12金水，今夜原定验7，可惜未能落验，故7绝非我的金水，别误传。3、7号首轮站6，但3号最终回票6，7号仍投我，7号狼面最高；我信逻辑，不信遗言污金水。
```

切句结果：

```text
1. 六号开枪,铁狼王,我是真预言家.
2. 昨夜验十二金水,今夜原定验七,可惜未能落验,故七绝非我的金水,别误传.
3. 三,七号首轮站六,但三号最终回票六,七号仍投我,七号狼面最高,我信逻辑,不信遗言污金水.
```

第 1 句与第 2 句之间 500ms，第 2 句与第 3 句之间 500ms。

## 服务器

`new-server.py` 以现有 `server.py` 为起点，只在这个文件里增加切句和拼接。默认 `--port 3003`。音色目录仍是 `wolf-audio/{agentName}.wav`。

同一把推理锁内按句子顺序合成。一句失败则整次请求失败，不返回半成品。日志打印句子序号、句子总数和该句耗时。

每句调用现有合成入口时，句内的 `interval_silence` 设为 0。500ms 只由 `new-server.py` 加在句与句之间。某一句仍超过 `max_text_tokens_per_segment` 时，沿用模型内部的长度切分，那些内部切口不加 500ms。

`duration_factor` 默认 `1.0`，每一句使用同一个值。

### `POST /split`

只切句，不合成。请求体与下面的 `/tts` 使用同一套文本和语言字段。

响应 JSON：

```json
{
  "sentences": ["六号开枪,铁狼王,我是真预言家.", "..."],
  "silence_ms": 500
}
```

`/split` 和 `/tts` 必须调用同一个切句函数。

### `POST /tts`

请求字段与现有 `/tts` 对齐：

| 字段 | 默认 | 说明 |
|---|---|---|
| `agentName` | 必填 | 对应 `wolf-audio/{agentName}.wav` |
| `text` | 必填 | 原文 |
| `lang` | `ZH` | IndexTTS 2.5 语言 |
| `duration_factor` | `1.0` | 每句相同 |
| `num_beams` | `1` | 沿用现有含义 |
| `n_timesteps` | 服务启动值 | MLX |
| `max_text_tokens_per_segment` | `120` | 只作用于单句内部 |

响应 JSON：

```json
{
  "sentences": ["..."],
  "silence_ms": 500,
  "audio_base64": "<mp3 bytes, base64>",
  "media_type": "audio/mpeg"
}
```

错误沿用现有语义：音色文件不存在返回 404，空文本或非法语言返回 400，合成没有产出音频返回 500。

### `GET /health`

返回服务状态、模型版本和后端名称，供新界面确认 `new-server.py` 已起来。

## 界面

`new-webui.py` 是 Gradio 页面，默认 `7861`，通过 HTTP 调用 `new-server.py`（默认 `http://127.0.0.1:3003`）。页面只保留这条合成路径，不移植情感向量、实验功能和预设。

页面内容：

- 音色下拉框，选项来自 `wolf-audio/*.wav` 的文件名（去掉扩展名）。
- 语言，默认 `ZH`。
- 原文输入框。
- 生成按钮。
- 切句列表，展示 `/split` 或 `/tts` 返回的 `sentences`，顺序与拼接顺序一致。
- 音频播放器，播放最终 mp3。

生成开始后按钮不可重复提交。切句结果先出现，合成期间页面保持等待状态。成功后播放器载入整段音频。失败时显示服务器返回的错误，不清空原文。

## 验收

- 上文示例被切成列出的 3 句；逗号和由 `；`、`、` 转来的逗号都留在句内。
- 3 句按顺序拼接，两个接头各约 500ms 静音，结尾没有额外的 500ms。
- 只有一句、且没有句末标点的文本，只合成一次，不插入 500ms。
- 连续句号不会产生空句，也不会多一次合成。
- 未知音色返回 404；空文本返回 400。
- 播放器能播放返回的 mp3。
- `webui.py` 和 `server.py` 的内容不因本次改动而变化。
- 只启动 `new-webui.py` 时不会把模型再加载进内存。
