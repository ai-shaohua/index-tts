# 句末与分号切分合成

日期：2026-10-18  
状态：待实现  
涉及文件：`new-server.py`、`new-webui.py`  
不改文件：`webui.py`、`server.py`

## 问题

IndexTTS 把一段发言整段送进模型。句号只影响模型自己带出来的气口，没有固定时长。文本归一化还会把分号 `；` `;` 收成逗号，分号和逗号在送进模型之前就没有区别了。长文本的分段又按 token 预算切，不按句末切。结果是音色像，句末停顿偏短，分号该有的中间停顿也丢了。

狼人杀发言通常两三句，句中还会用分号分开两个分句。用户要的是：原文先归一化，分号保留为分号；再按句末和分号切开，逐段生成，按原顺序拼成一条可播放的音频。句末后面 500ms，分号后面是句末的 2/3。

## 目标

1. `new-server.py` 收到原文后做文本归一化。数字、句号、问号、感叹号、逗号、顿号、冒号仍按 IndexTTS 2.5 的现有规则处理。唯一的例外是 `；` 和 `;` 不得变成逗号。
2. 归一化之后按句末标点和分号切段。每段单独合成，再按原顺序拼接。
3. 停顿由切分点决定，加在音频上，不加在最后一段之后：
   - 句末（`.` `!` `?`）后面 **500ms**
   - 分号（`;`）后面 **333ms**，即 `round(500 × 2 / 3)`
4. `new-webui.py` 提供一个新界面：选音色、输入原文、看到切出来的段落和每段后面的停顿、播放最终音频。
5. 切分、逐段生成、按标点拼接全部在 `new-server.py` 内完成。`new-webui.py` 不加载模型，也不自己切句或拼音频。
6. `webui.py` 和 `server.py` 保持现状。现有路径里分号仍会被收成逗号，这次不改它们。

## 非目标

- 不给逗号、顿号、冒号单独加停顿。它们仍收成逗号，留在段内，停顿仍由模型生成。
- 不把分号停顿做成可调滑块。333ms 是 500ms 的 2/3，跟句末停顿绑在一起。
- 不在界面上逐段改稿、调每段的停顿或情感。
- 不把生成过程流式推到播放器。界面等整段拼接完成后再播放。
- 不在 `new-webui.py` 里加载第二份模型权重。同一时刻只跑一个带模型的进程。
- 不修改 `indextts/utils/front.py` 的共享 `char_rep_map`。那个表会改变现有 `webui.py` / `server.py` 的行为。分号保留只发生在 `new-server.py` 自己的归一化里。

## 用户流程

1. 启动 `new-server.py`（默认端口 `3003`），再启动 `new-webui.py`（默认端口 `7861`）。两者可与现有的 `server.py`（`3002`）和 `webui.py`（`7860`）同时存在，但不要同时加载两份模型。
2. 在新界面选择 `wolf-audio` 里的音色，语言默认中文，粘贴发言原文。
3. 点击生成。界面先显示切段结果和每段后面的停顿毫秒数，再等待合成。
4. 合成结束后，播放器播放拼接好的整段音频。

## 归一化

切段发生在文本归一化之后、逐段合成之前。界面展示的段落必须和实际送去合成的段落是同一份结果。

`new-server.py` 沿用 IndexTTS 2.5 的中文路径：先做标点替换，再走 WeTextProcessing。相对共享 `char_rep_map`，只改分号：

| 原文 | 新服务器里的结果 |
|---|---|
| `。` | `.` |
| `！` | `!` |
| `？` | `?` |
| `；` `;` | `;`，不得变成 `,` |
| `，` `、` `：` `:` | `,` |
| `……` `...` | `…` |
| 换行 | 空格 |
| `6` `12` 这类数字 | 六、十二，规则与现有归一化相同 |

现有 `infer()` 在合成前仍会用共享 `char_rep_map` 把 `;` 收成 `,`。因此新服务器必须自己完成上述归一化，再把已经归一化的段落送去合成，并关掉这条会改写分号的文本清洗。否则分号会在切段之后又变回逗号，展示文本和实际合成文本就会不一致。

## 切段规则

切在这些标点后面，标点留在该段末尾：

- 句末：`.` `。` `!` `！` `?` `？`。归一化之后实际看到的是 `.` `!` `?`。
- 分号：`；` `;`。归一化之后实际看到的是 `;`。

不切：

- `,` `，` `、` `：` `:`
- `…`
- 换行

其他约定：

- 没有句末标点、也没有分号的剩余文本仍作为最后一段。
- 切完后去掉空段，不为空段发合成请求。连续的 `。。` 或 `；；` 不产生空段。
- 只有一段时不插入停顿。
- 最后一段后面不插入停顿。
- 标点留在送进模型的文本里。500ms 和 333ms 是拼到音频上的静音，不是再写进文本的符号。
- 某一段后面的停顿只看这一段末尾的标点：`.` `!` `?` 为 500ms，`;` 为 333ms。

用下面这段原文验收。顿号仍变成逗号并留在段内；分号单独切开，不再和后面的「我信逻辑」粘在同一段。

原文：

```text
6号开枪，铁狼王，我是真预言家。昨夜验12金水，今夜原定验7，可惜未能落验，故7绝非我的金水，别误传。3、7号首轮站6，但3号最终回票6，7号仍投我，7号狼面最高；我信逻辑，不信遗言污金水。
```

切段结果：

```text
1. 六号开枪,铁狼王,我是真预言家.          后面 500ms
2. 昨夜验十二金水,今夜原定验七,可惜未能落验,故七绝非我的金水,别误传.    后面 500ms
3. 三,七号首轮站六,但三号最终回票六,七号仍投我,七号狼面最高;    后面 333ms
4. 我信逻辑,不信遗言污金水.                后面没有额外停顿
```

## 服务器

`new-server.py` 以现有 `server.py` 为起点，在这个文件里增加分号保留、切段和拼接。默认 `--port 3003`。音色目录仍是 `wolf-audio/{agentName}.wav`。

同一把推理锁内按段落顺序合成。一段失败则整次请求失败，不返回半成品。日志打印段落序号、段落总数、该段末尾标点和该段耗时。

每段调用合成入口时，段内的 `interval_silence` 设为 0。500ms 和 333ms 只由 `new-server.py` 加在段与段之间。某一段仍超过 `max_text_tokens_per_segment` 时，沿用模型内部的长度切分，那些内部切口不加 500ms 或 333ms。

`duration_factor` 默认 `1.0`，每一段使用同一个值。

### `POST /split`

只切段，不合成。请求体与下面的 `/tts` 使用同一套文本和语言字段。

响应 JSON。`silences_ms[i]` 是 `sentences[i]` 后面的停顿，长度比 `sentences` 少 1：

```json
{
  "sentences": [
    "六号开枪,铁狼王,我是真预言家.",
    "昨夜验十二金水,今夜原定验七,可惜未能落验,故七绝非我的金水,别误传.",
    "三,七号首轮站六,但三号最终回票六,七号仍投我,七号狼面最高;",
    "我信逻辑,不信遗言污金水."
  ],
  "silences_ms": [500, 500, 333]
}
```

`/split` 和 `/tts` 必须调用同一个切段函数。

### `POST /tts`

请求字段与现有 `/tts` 对齐：

| 字段 | 默认 | 说明 |
|---|---|---|
| `agentName` | 必填 | 对应 `wolf-audio/{agentName}.wav` |
| `text` | 必填 | 原文 |
| `lang` | `ZH` | IndexTTS 2.5 语言 |
| `duration_factor` | `1.0` | 每段相同 |
| `num_beams` | `1` | 沿用现有含义 |
| `n_timesteps` | 服务启动值 | MLX |
| `max_text_tokens_per_segment` | `120` | 只作用于单段内部 |

响应 JSON：

```json
{
  "sentences": ["..."],
  "silences_ms": [500, 333],
  "audio_base64": "<mp3 bytes, base64>",
  "media_type": "audio/mpeg"
}
```

错误沿用现有语义：音色文件不存在返回 404，空文本或非法语言返回 400，合成没有产出音频返回 500。

### `GET /health`

返回服务状态、模型版本和后端名称，供新界面确认 `new-server.py` 已起来。

## 界面

`new-webui.py` 是 Gradio 页面，默认 `7861`，通过 HTTP 调用 `new-server.py`（默认 `http://127.0.0.1:3003`）。页面只保留这条合成路径，不移植情感向量、实验功能和预设。

页面内容：

- 音色下拉框，选项来自 `wolf-audio/*.wav` 的文件名（去掉扩展名）。
- 语言，默认 `ZH`。
- 原文输入框。
- 生成按钮。
- 切段列表，展示 `sentences`。除最后一段外，每一段标明后面的停顿（500ms 或 333ms）。
- 音频播放器，播放最终 mp3。

生成开始后按钮不可重复提交。切段结果先出现，合成期间页面保持等待状态。成功后播放器载入整段音频。失败时显示服务器返回的错误，不清空原文。

## 验收

- 上文示例被切成列出的 4 段。`、` 变成的逗号留在第 3 段内部。`；` 变成 `;` 并留在第 3 段末尾，不变成逗号。
- 四个接头的停顿依次是 500ms、500ms、333ms。最后一段后面没有额外停顿。
- 只有一段、且没有句末标点或分号的文本，只合成一次，不插入停顿。
- 连续句号、连续分号不会产生空段，也不会多一次合成。
- 冒号 `：` 仍变成逗号，不切段。
- 未知音色返回 404；空文本返回 400。
- 播放器能播放返回的 mp3。
- `webui.py`、`server.py` 和共享 `char_rep_map` 的内容不因本次改动而变化。现有界面里分号仍按原规则收成逗号。
- 只启动 `new-webui.py` 时不会把模型再加载进内存。
